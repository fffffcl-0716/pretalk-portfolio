Why this exists

它解决的不是“写得更长”，而是“写得更有用”

Pretalk 信息通常散在十几分钟的对话里。真正影响后续面试判断的内容，需要被提炼出来，而不是被一股脑堆进备注框。

01 / 信息分散

通话结束，重点还在录音里

HR 需要从自然对话中找到状态、薪资和候选人当前的变动动机。

02 / 原因失真

“个人发展”解释不了变化

在职与离职的原因往往有多层背景，笼统概括会让后续面试官失去判断依据。

03 / 口径不一

每个人写出的备注都不一样

统一日期、长度和重点，让备注可以直接归档，也方便不同角色快速扫描。

How it works

三步拿到智能记录链接

在通话中开启智能记录，结束后复制记录内容，再将其交给智能助手生成系统备注。

01 · 开智能记录

选择“智能记录”，让通话生成可检索的会议内容。

02 · 点更多

通话界面底部点“···”，进入更多功能。

03 · 复制链接

结束后打开会议助理，点击“复制链接”。

Output design

把“变动原因”放在结果中心

输出是一段约 100–150 字的中文备注，以日期开头，优先保留能帮助面试官判断的事实。

ANONYMIZED OUTPUT SAMPLE
20261120候选人目前在职，计划寻找新的发展机会，主要原因是当前业务进入稳定阶段，工作内容重复度较高，团队调整后可承担的职责边界变窄，希望寻找更有成长空间的岗位。当前月薪约2.5万，期望薪资在现有基础上有一定涨幅，接受北京base，暂无明确其他offer。
A
在职候选人写清为什么现在看机会：业务、岗位、团队、发展、薪酬或阶段目标，避免只写“想看看机会”。
B
离职候选人写清为什么离开、主动还是被动，以及离开后到现在在做什么，保留通话中的关键事实。
C
信息边界只基于通话原文，不猜数字，不扩展成画像、评分或面试评价。
Implementation

把自然对话变成可用招聘信息

这是一个面向真实工作流的 AI 信息提取设计：先限定事实边界，再根据候选人状态选择不同的提炼规则，最后输出统一格式。

PUBLIC IMPLEMENTATION LOGIC
1. 读取通话转写并识别候选人状态、薪资、地点与其他机会。

2. 在职时优先解释“为什么现在看机会”；离职时优先解释“为什么离开、离开后做了什么”。

3. 仅保留通话中出现的事实，缺失信息标注“未提及”或直接省略。

4. 按固定字数和格式生成一段可直接入库的中文备注。
1
输入标准化将智能记录或转写内容转换为统一文本输入，避免要求 HR 重复填写表单。
2
规则优先的提取先识别状态，再匹配对应的变动原因规则，防止“个人发展”等空泛表述覆盖具体事实。
3
受约束的生成通过日期、字数、单段输出和禁止项约束结果，确保可直接贴入招聘系统。
Use it

输入足够简单，结果直接可用

技能面向真实招聘工作流设计，不需要额外填写复杂表单。

输入

[智能通话记录或转写内容] 备注

将智能通话记录或转写内容与“备注”指令一起发送。没有智能记录时，也可以直接贴转写文字。

适用位置

业务筛选通过之后、正式面试之前的电话 pretalk。它帮助后续面试官快速了解候选人的当前状态、变动动机和关键意向。

面试全部通过、收材料之前的确认电话属于另一类流程，应使用候选人信息整理能力。
